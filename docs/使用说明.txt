深空堆栈工具 使用说明（详细版）
================================
适用版本：DeepSkyStacker.exe（图形界面）/ DeepSkyStacker_CLI.exe（命令行）
更新：2026-11

--------------------------------------------------------------------------------
一、这个程序做什么
--------------------------------------------------------------------------------
把一批 RAW 亮场（可选暗场、平场）自动对齐、剔除异常、叠加成一张低噪声的
线性 16bit TIFF，并可选做去光污染、色度降噪、预览图、目标识别。

完整流程：
  RAW 解码 → 主暗场合成 → 主平场合成 → 星点检测 → 帧间配准
  → 叠加（三种方式可选）→ 去马赛克 → 裁到公共覆盖区
  → 去背景（可选）→ 色度降噪（可选）→ 保存（自动加基底）
  → 生成预览图 → 目标识别（可选）

输出的 TIFF 是**线性数据**：没拉伸、没校色、没有 gamma，
所以在看图软件里会显得很黑，信息量则是完整的。

--------------------------------------------------------------------------------
二、快速上手
--------------------------------------------------------------------------------
图形界面：
  1. 双击 app\DeepSkyStacker.exe
  2. 亮场文件夹：选放 ARW 的目录
  3. 暗场/平场文件夹：有就选，没有留空
  4. 叠加方式：默认自动（检测到 gpu_runtime 就用 GPU）
  5. 点“开始堆栈”
  6. 成品在 app\output\<堆栈开始时刻>.tif

命令行：
  cd /d <安装目录>\app
  DeepSkyStacker_CLI.exe --cli --lights "D:\lights" --darks "D:\darks" --flats "D:\flats" --threads 8

--------------------------------------------------------------------------------
三、输入：亮场 / 暗场 / 平场
--------------------------------------------------------------------------------
【亮场 Lights】
  你的目标照片。程序按文件名排除含 dark/flat/bias 的文件，其余都当亮场。
  程序按 EXIF 拍摄时间排序（保证对齐顺序稳定）。

【暗场 Darks】
  与亮场同 ISO、同曝光、同温度、盖镜头盖拍的片子。
  作用：扣掉传感器固定图案噪声（FPN）、热点、暗电流。
  影响：不扣暗场 → 背景会有固定的横向/纵向纹理和零星亮热点，
        堆得越多越明显；扣得好 → 背景更干净、暗部更均匀。
  需要多少张：20~50 张就够；本工具会自动做 4σ 裁剪平均。

【平场 Flats】
  对着均匀光源（白板/天光）拍的、与亮场同光圈同对焦的片子。
  作用：扣掉镜头渐晕（四角变暗）、灰尘影、像素响应不一致。
  影响：**这是影响画面“品质感”最大的一项**。
        · 有平场：背景亮度均匀、颜色一致、四角不暗；
        · 没平场：四角明显变暗、中心偏亮、去背景算法容易把大片区域误判成光害，
          单色/彩色渐变都去不干净。
  需要多少张：20~50 张；本工具按 CFA 四个通道分别归一化（关键，否则颜色会被抹平）。

【文件夹里混了别的片子怎么办】
  程序只按文件名前缀排除 dark/flat/bias；如果你的测试片叫 DSC00001 之类，
  会被当成亮场。建议把三类片子分目录存放。

--------------------------------------------------------------------------------
四、核心参数
--------------------------------------------------------------------------------
【σ 剔除倍数 κ（默认 3.0）】
  叠加时逐像素比较：某帧的值偏离当前均值超过 κ×σ 就丢弃该像素。
  作用：去掉卫星轨迹、飞机、飞鸟、云、宇宙线、热像素等偶发异常。
  κ 小（2.0~2.5）：剔除更狠，伪影去得干净，但可能误杀暗弱信号，可用帧数变少。
  κ 大（4.0~5.0）：保守，保留更多帧，伪影可能残留。
  推荐：帧数多（>200）用 2.5~3.0；帧数少（<30）用 3.5~4.0。

【线程数（默认 = CPU 核数一半）】
  影响 RAW 解码与重采样的并行度。
  · CPU 模式：设到物理核心数（8）附近收益最大，再往上会被内存带宽限制。
  · GPU 模式：只影响“解码预取”的线程数，GPU 计算只有一条流水线。
  影响：只影响速度，不影响画质。

【叠加方式】
  · 原版(两遍叠加)：第一遍统计每像素均值/σ，第二遍按 κσ 剔除。
      最保守、结果最“标准”，但每帧要解码+重采样两次，最慢。
  · CPU 单遍优化：一遍完成，边累加边用运行中的均值/σ 剔除。
      速度约为原版的 1.5 倍；与两遍结果差异极小（实测 0.4 ADU，噪声 σ≈100）。
  · GPU 加速：单遍 + 重采样与累加都在显卡上（手写 Catmull-Rom 三次插值）。
      速度快 2~4 倍（帧数越多越明显）；噪声略低约 7%，星点锐度指标不变。
  三者画质等价，选哪个只影响速度。检测不到 GPU 时下拉框不显示 GPU 项。

  【快速重采样（默认关）】选项区勾选框 / 命令行 --fast-warp
    默认用三次插值（样条/Catmull-Rom）重采样对齐帧；勾选后改用双线性。
    实测（60 帧，CPU 单遍）：126.5s -> 111.1s（快 14%），
    代价是星点略软（星点面积中位 8.0 -> 9.0 px）、噪声 σ 略降（9.36 -> 7.50，
    因为双线性本身有低通效果）。追求星点锐度就别勾；赶时间可以勾。

--------------------------------------------------------------------------------
五、输出相关
--------------------------------------------------------------------------------
【自动裁剪到公共覆盖区域（默认开）】
  帧与帧之间有旋转/平移，边缘会出现黑角或错位。
  开：只保留所有帧都覆盖的公共区域（例如 6048×4024 → 5240×3200），画面干净。
  关：保留更大画幅，但四边会有黑边或半透明错位边。
  影响：成片的尺寸和你后期能用的画面范围。

【TIFF 输出白平衡版（默认关）】
  保存时乘上相机的白平衡增益（R×2.6、B×1.8 左右）。
  开：PS/看图软件打开颜色接近正常，只是偏暗（因为还是线性）。
  关：输出“相机原始 RGB”，绿通道最亮，看起来明显发绿。
  说明：只做增益、不做色彩矩阵（矩阵会把暗部压出偏色）。
  影响：只改 TIFF 数值，不改堆栈本身。

【输出内容（三选一，默认"线性 + 拉伸（都生成）"）】★新增
  堆栈结束后要生成哪种成品，直接在选项区"输出内容"里选：

  ┌──────────────────┬──────────────────────────────────────────────┐
  │ 线性 + 拉伸（默认）│ 两份都生成：<时刻>.tif + <时刻>_stretched.tif │
  │ 只生成线性 TIFF   │ 只出 <时刻>.tif（后期用，最完整）             │
  │ 只生成拉伸 TIFF   │ 只出 <时刻>_stretched.tif（打开就能看）       │
  └──────────────────┴──────────────────────────────────────────────┘
  命令行：--out-kind both|linear|stretch（默认 both）
  （旧参数 --no-stretch-out 仍然可用，等价于 --out-kind linear）

  两种文件的区别：
    · 线性 TIFF：未拉伸、未校色，PS 里打开是黑的。信息最全，
      做曲线、去星、合成等精细后期都用它。
    · 拉伸 TIFF：白平衡 → 提亮 → 逐通道扣背景 → asinh 拉伸 → 饱和度 +18，
      16bit、打开就能看，适合快速出片、发图、给客户看。
  怎么选：
    · 要正经后期 → 选"只生成线性"（省时间省空间）
    · 只想快速看效果 → 选"只生成拉伸"
    · 不确定 / 两者都要 → 默认"都生成"（多花 5~10 秒、多占 30~70 MB）
  饱和度：命令行 --stretch-sat 1.18 可调（1.0 = 不做饱和度增强）。

【额外输出 16bit PNG 预览（默认关）】
  在 JPG 预览之外，再输出一张全分辨率、无损、16bit 的彩色 PNG。
  影响：给后期留色深（8bit JPG 拉伸容易断层）；代价是多 30~60 MB 和时间。

【输出文件 / 默认目录】
  留空：输出到 exe 同目录 output\，文件名 = **堆栈开始时刻** YYMMDD_HHMM.tif
  （同名会自动加 _2、_3，不会覆盖）
  会同时生成：<时刻>_preview.jpg、<时刻>_preview.png(可选)、<时刻>_object.txt、<时刻>.log

--------------------------------------------------------------------------------
六、去光污染（重头戏，可以叠加使用）
--------------------------------------------------------------------------------
★ 傻瓜模式（推荐先用这个）
  界面上"去光污染"下拉框，只有五种选择：
    · 自动判断（推荐）→ 程序采样 3 帧，算出背景亮度和梯度，自动定档
    · 低（郊区/暗夜）
    · 中（城郊）
    · 高（城市）
    · 手动设置 → 下面那些勾选框才会启用
  选前四种时，程序自动套用预设，并把决定写进日志，例如：
    "自动判断光污染等级: high (背景中位 1678, 平面梯度 1433, 评分 2.53)"
    "光污染等级 high -> 逐帧去光污染 + Background2D 激进(q=30) + 结构保护 + 色度降噪 3"

  三档预设分别是：
  ┌────┬──────────────────────────────────────────────────────────┐
  │ 低 │ Background2D(q=40) + 结构保护，不逐帧处理                  │
  │ 中 │ Background2D(q=35) + 结构保护 + 色度降噪 2                 │
  │ 高 │ 逐帧去光污染 + Background2D 激进(q=30) + 结构保护 + 色度降噪3│
  └────┴──────────────────────────────────────────────────────────┘
  （q 是"背景地板分位数"：数值越小去得越狠。M42 这批数据实测 q=45 时中心光晕
    还留一圈，q=40 才干净；强光害再往下压到 30。）
  额外规则：**没提供平场时会自动上调一档**（低→中、中→高），
  因为渐晕没法用平场扣，只能靠更激进的去背景兜底。

  自动判断的算法：采样前 3 帧，算 ① 背景亮度中位数 ② 平面拟合后的梯度幅度，
  合成评分 = 背景中位/1000 + 相对梯度；<0.8 低、<1.8 中、其它 高。
  实测：M42(2016，有平场) 评分 0.55 → 低；ISO100 银河 1.28 → 中；
        ISO400 银河 2.53 → 高。判得挺准，可以直接信。

  命令行：--lp-level auto|low|mid|high|manual（默认 manual，保持老脚本行为不变）

★ 按目标类型优化（默认开，界面勾选框"按目标类型优化"）
  识别出目标之后，程序会读它的**类型**，再微调去背景参数：

  ┌────────────┬─────────────────────────────────────────────────────────┐
  │ 目标类型   │ 自动调整                                                 │
  ├────────────┼─────────────────────────────────────────────────────────┤
  │ 星团       │ 结构保护关、Background2D(q=45)、不降噪                   │
  │ (OCl/GCl)  │ 理由：全是点源，没有大尺度结构要保护，去背景可以更狠       │
  │ 星云       │ 结构保护开、Background2D(q=40)、色度降噪 1               │
  │ (Neb/HII/  │ 理由：大尺度柔光最容易被当光害吃掉                        │
  │  RfN/SNR)  │                                                         │
  │ 星系       │ 结构保护开、Background2D(q=50)、关逐帧去光污染、不降噪     │
  │ (G)        │ 理由：暗弱外晕表面亮度低，激进去背景会直接抹掉            │
  │ 行星状星云 │ 结构保护开、Background2D(q=50)、不降噪                    │
  │ (PN)       │ 理由：颜色是核心特征，降噪会洗掉                          │
  └────────────┴─────────────────────────────────────────────────────────┘

  执行顺序：先按"去光污染等级"套预设，再按目标类型覆盖。
  例外：若光污染等级是"高"，类型优化不会抬高 q（强光害下以去渐变为先）。

★ 视场检查（防止瞎猜）
  按类型优化前会先算出**对角视场**，只在**可用星表覆盖范围内**才做类型优化。
  视场来源按优先级：
    1) EXIF 的 35mm 等效焦距（0xA405）—— 与画幅无关，最稳
    2) EXIF 实际焦距（0x920A）+ FocalPlaneXResolution（0xA20E）
       反推传感器尺寸，算出真实视场
    3) EXIF 实际焦距 + 按 APS-C 画幅估算（兜底）
    4) 都没有？用**星场解算结果**里的视场（自动识别成功时一定有）
  日志会写明来源和判定，例如：
    "视场 5.5° (EXIF), 可用星表覆盖 4.0°~30.0° -> 在范围内"
    "视场超出星表范围, 不做按类型优化(可用'手动指定'强制启用)"
    "视场 12.0° (星场解算), 可用星表覆盖 10.0°~30.0° -> 在范围内"

  **手动指定目标会跳过视场检查**：
    "目标为用户手动指定, 跳过视场检查"
  因为用户已经明确告诉程序目标是谁，没必要再用视场去猜。
  这样窄视场（比如 300mm 的 5.4°）也能用手动指定 + 类型优化。

  四种情形对照：
  ┌──────────────────────┬──────────────────────────────┐
  │ 情形                 │ 行为                         │
  ├──────────────────────┼──────────────────────────────┤
  │ 自动识别 + 有 EXIF   │ 按 EXIF 视场判断，超范围就跳过│
  │ 自动识别 + 无 EXIF   │ 用星场解算出的视场判断        │
  │ 自动识别 + 两者都没  │ 照常优化（日志标明"无视场信息"）│
  │ 手动指定             │ 跳过检查，直接优化            │
  └──────────────────────┴──────────────────────────────┘

  关闭方式：取消勾选"按目标类型优化"，或命令行 --no-type-opt。

--- 下面是手动模式的说明，选"手动设置"时才需要看 ---

先说结论：
  强光害、无平场（城市银河）→ 勾【逐帧去光污染】+【Background2D】+【结构保护】
  有平场、背景本来就平（深空小目标）→ 只勾【Background2D】，或干脆都不勾
  轻微渐变 → 【多项式 2 阶】就够

【逐帧去光污染 --lp】
  在每一帧、配准之前，对 4 个 CFA 平面分别拟合背景并减掉。
  原理：光害/渐晕固定在传感器坐标上，逐帧扣比叠加后扣更准，不会把银河当渐变挖掉。
  影响：
    · 好处：城市光害的强梯度、四角渐晕被大幅压平；对无跟踪的旋转序列尤其有效。
    · 代价：每帧多花 0.5~0.8 秒（500 帧约多 5 分钟）。
    · 注意：扣除后像素会出现负值，程序会自动加基底保留（见第九节），不会丢掉暗部。
  什么时候别用：有平场且背景本来干净时，逐帧扣可能过度修正，建议关掉。

【--lp-div（除法模式）】
  用“除以背景面”代替“减去背景面”，适合纯乘性的渐晕。
  实测在本类数据上减法更好，默认用减法。

【Background2D 去背景 --bg2d（默认开）】
  叠加完成、去马赛克之后，逐通道做：
    网格切块(约 20×28) → 每块取背景地板分位数 → 中值滤波 → 三次插值成平滑背景面 → 减掉
  影响：
    · 去掉中/大尺度的天空渐变（光害穹顶、月光、薄云）；
    · 会让整体亮度略有下降（背景被压到接近 0）。
  q 值（地板分位数，默认 40）：
    20~35 → 更激进，渐变去得狠，但可能把星云/银河的大尺度亮部一起减掉；
    50~60 → 保守，星云保留好，光害残留多。
  它是“网格法”，对陡峭的强光害穹顶效果最好，且不需要任何模型文件。

【结构保护 --bg-protect（默认开）】
  做法：先拟合一次背景 → 找出明显高于模型的区域（星云、银河核心）→ 把它们排除出
  建模样本 → 重新拟合，迭代 2~3 次。
  影响：
    · 显著减少“把银河/星云当光害减掉”的问题（这是早期版本细节丢失的主因）；
    · 代价：Background2D 的耗时增加约 2~4 倍（几百像素的全幅图约多几十秒）。
  建议：拍星云、银河时开；拍纯星野/星团可以关。

【RBF 背景提取 --rbf [平滑量]（默认关）】
  薄板样条插值背景（与 Siril 的 RBF 插值法同类）。
  特点：背景非常平滑，但逐通道拟合时容易在亮区留下彩色斑块。
  适用：渐变较缓、希望背景极平滑时；强光害不如网格法。
  注意：**和 Background2D 互斥**。若已勾 Background2D，程序会跳过 RBF（日志写明），
        避免两层去背景叠加把星云压平。要用 RBF 请先取消 Background2D。

【多项式曲面 --bg-poly N（默认关）】
  用二维多项式拟合背景：1=平面（纯线性渐变）、2~4=曲面。
  影响：非常温和，不会挖掉结构；但**拟合不了陡峭的光害穹顶**，强光害数据会留一片亮斑。
  适用：有平场的深空图、轻微背景倾斜。

【背景平整（叠加后）--flatten（默认关）】
  旧算法：重度模糊估计背景再减。会削掉银河的大尺度结构，已被 Background2D 取代。
  保留只为兼容旧流程。

【色噪去除 --chroma-denoise（默认关）】★新算法
  位置：选项区「色噪去除」下拉框（关 / 轻 / 中 / 强）
  命令行：--chroma-denoise off|light|medium|strong   --chroma-scales 3

  算法：只处理色度，亮度完全不动。
    RGB -> Y + (R-Y, G-Y, B-Y)，把三个色差平面各做一次 à trous 小波降噪，
    再合成回 RGB。色噪是"斑块状"的低频误差，小波按尺度压掉；亮度通道不受影响，
    所以星点锐度和细节一点都不损失。
    色度先在 1/2 分辨率上去噪再放大，快约 4 倍（色噪本身低频，几乎无损）。

  强度档位：轻=0.35 / 中=0.55 / 强=0.75
  实测（40 帧 ISO400 银河）：色噪 σ 14.05 -> 7.53（中）；
  旧的高斯模糊 sigma=2 只能降到 8.88，而且会把彩色细节糊成一片。

  旧算法仍保留：--chroma-nr 2~4（高斯模糊色度）。两个同时给时新算法优先。

  什么时候用：
    · 强光害、帧数少、拉伸后满屏红绿斑 -> 用「中」或「强」
    · 只想压一点彩色噪点、保留星点颜色 -> 用「轻」
    · 行星状星云、彩色双星这类"颜色就是主体"的目标 -> 慎用或关掉

【小波降噪 --denoise（默认关）】★新增
  位置：选项区「小波降噪」下拉框（关 / 轻 / 中 / 强）
  命令行：--denoise off|light|medium|strong   --denoise-scales 4（层数，默认 4）

  算法：à trous（starlet）小波降噪 —— 天文摄影常用的 Starck 多尺度去噪。
    1) 用 B3 样条核做 4 层 à trous 分解，得到 4 个尺度的"细节层"；
    2) 每层用 MAD 估噪声 σ，软阈值 k·σ·强度（k=3）抑制小系数；
    3) 星点、星云边缘属于"大系数"，基本不动 —— 所以去噪但不糊星点。

  只处理**亮度**（噪声主要感知在亮度上），色噪交给「色度降噪」。
  强度档位：轻=0.30 / 中=0.50 / 强=0.70
  实测（20 帧猎户座，24MP）：背景噪声 σ 21.5 → 8.2（中）/ 6.7（强），
  星点面积 9.0 不变、峰值只掉 1~4%；每张多花约 2.5 秒。

  什么时候用：
    · 帧数少（<50）、ISO 高、拉伸后噪点明显时，用"中"最划算；
    · "强"会把暗部细节一起磨平，除非只想出图发朋友圈；
    · 帧数很多（>200）本身噪声就低，用"轻"或不降噪。
  和色度降噪的关系：小波降噪管"颗粒感"，色度降噪管"彩色斑块"，两个可以同时开。
  傻瓜模式已经自带：低=不降噪、中=0.30、高=0.45。

【手动模式下的完整控件一览（界面"选项"区，选"手动设置"才启用）】
  逐帧去光污染 [开]  + 方式 [减法/除法]

七、目标识别
--------------------------------------------------------------------------------
【自动识别目标（默认开）】
  用内置 tetra3 星表对星场做盲解（求 RA/Dec/视场/旋转），再查 278 个
  Messier/NGC/IC 目录得到名字。识别结果写入 _object.txt。
  内置两个星表：窄视场 4°~8°、中等 10°~30°。
  窄视场会自动换用"小视场专用"的星点质心算法，并对首/中/尾三帧依次尝试，
  单帧失败也能兜住。
  影响：只影响“名字”，不影响堆栈像素。
  失败原因：视场不在星表范围（内置星表覆盖约 10°~30° 对角视场），
            例如 300 mm 镜头只有 5.4°，会识别失败 → 显示“未知”。

【或手动指定】
  直接选一个名字（优先于自动识别）。窄视场、星表解不出时用它。

【单独识别星空…（按钮）】
  不堆栈，只识别一张图或 RAW。会先弹“识别选项”对话框：
    画幅（APS-C / 全画幅 / M4/3 / 1英寸…）、裁切系数、焦距 mm、星表
  前两项可留空：都留空 → 依次尝试所有星表；填了画幅+焦距 → 按对角视场自动挑星表。
  影响：只影响识别成功率。

--------------------------------------------------------------------------------
八、成品加工（不堆栈的两个功能）
--------------------------------------------------------------------------------
【加白边成品…】
  给一张照片加白边，底部用黑字写天体名称；可自动识别或手动指定目标。
  影响：生成 <原名>_framed.jpg，不改变原始像素。

【自动拉伸…（--stretch）】
  把线性 TIFF 变成“能看的图”：白平衡 → 提亮 64× → 逐通道扣背景 → asinh 拉伸 → 饱和度+18。
  输出 <原名>_stretched.tif（16bit）和 .jpg。
  影响：只是显示用的成品，不动原始 TIFF；拉过之后暗部噪声也会一起被放大。

【星点处理：缩星 / 去星（叠加时自动做）】★
  位置：选项区「星点处理」下拉框 + 强度数字框（默认"不处理"）
  命令行：--star-mode off|reduce|remove   --star-strength 0~1（默认 0.85）

  两种模式：
    · 缩星（reduce）：保留星点，只压掉外晕，让星星变小变干净。
      输出 <时刻>_starred.tif + 拉伸版 _starred_stretched.tif/.jpg
    · 去星（remove）：把星点从画面里去掉，输出无星版 + 星点层。
      输出 <时刻>_starless.tif、<时刻>_starless_stars.tif、_starless_stretched.*

  主成品 <时刻>.tif **仍然是没做星点处理的原始叠加**，星点处理只额外产出上面那些文件，
  这样你可以同时拿到"未处理的主成品 / 缩星版 / 无星版"三份文件，互不覆盖。

  工作原理（纯算法，不依赖 AI 模型）：
    1) 多尺度高通找点源（1.2/2.5/3/5 像素取最大），面积过小（噪点）和过大（星云团块）的
       连通块丢掉，只留真正的点源；阈值用局部 MAD，密星场不会整片误判；
    2) 按每颗星的半径自适应膨胀掩膜；
    3) 归一化卷积从周围未遮挡像素估计星点下面原本的星云/背景；
    4) 去星 = 用估计值替换星点区域；缩星 = 只把外晕拉向估计值。

  参数怎么调：
    强度        去星默认 0.90（1.0=完全替换）；缩星建议 0.6~0.9
    什么时候用  星云目标（M42 这类）用去星；银河广角等密星场用缩星
    日志会打印掩膜覆盖率：
      · 12%~35% 会提示"星场较密，建议改缩星"，但仍会执行；
      · 超过 35% 判定为误检（多半是帧数太少、噪声太高），直接跳过星点处理，
        不会输出垃圾星点层。

  已知局限：
    · 过曝带大光晕的亮星可能残留；
    · 密星场去星会把星点组成的漫射光一起带走，产生暗斑 —— 优先用缩星。

----------------
九、输出文件与“基底（pedestal）”
--------------------------------------------------------------------------------
TIFF 里的数值 = 14bit 原始值 × 4（65535 = 16383）。
因为做过逐帧/叠加后去背景，像素会出现负值。如果直接裁成 0，
会出现“画面一侧整片纯黑、信息全丢”的问题（初版就踩过这个坑）。
现在保存时会检查最小值：若为负，整体抬一个基底（几十~一百多 ADU），
日志会打印“已加基底 N”。
影响：TIFF 的背景电平不再是 0，而是一个小偏置；后期在 PS/PixInsight 拉曲线时
      把黑场设到这个偏置之上即可，暗部信息不会丢。

预览图（_preview.jpg / .png）是拉伸过的**显示图**，只用于看效果，不能用于后期。

--------------------------------------------------------------------------------
【JPG 输出：浮点超采样（默认开启，无需设置）】★改进
  以前：先把浮点图量化成 8bit -> 再 LANCZOS 缩小 -> 存 JPG
        问题：8bit 台阶被一起缩放、亮星高光在缩放前就被裁到 255、
              Lanczos 的负瓣在亮星周围出轻微振铃。
  现在：浮点域直接 LANCZOS 缩小（PIL 会按比例展宽滤波核，等效抗混叠）
        -> 量化前加 ±0.5 LSB 三角抖动 -> 最后裁到 0~255 -> 存 JPG。
        好处：不再"先截断再平均"，暗部渐变不会被压成一条条色带。

  参数（命令行）：
    --jpg-max 2600      JPG 长边像素上限（默认 2600，预览图固定 2200）
    --jpg-quality 92    JPG 质量（默认 92）
  实测（20 帧 M42，2600px）：旧 2.81 MB / 新 2.67 MB，体积不变略小，
  棋盘测试的混叠程度两者相当（σ 0.0020 vs 0.0018）；
  渐变区旧版是 1 LSB 的平台台阶，新版被抖动打散，肉眼看不出色带。
  代价：多约 0.5 秒。

  注意：16bit TIFF / PNG 仍是全分辨率、不缩放、不抖动（给后期用的）。

十一、常见问题
--------------------------------------------------------------------------------
Q: 堆出来的 TIFF 打开一片黑？
A: 正常。它是线性数据（没有 gamma、没有拉伸），需要拉伸后才能看。
   用“自动拉伸…”按钮，或后期软件里拉曲线。

Q: 画面一侧整片死黑、没有星星？
A: 老版本会把负值裁成 0。新版本会自动加基底，请用最新 exe；
   如果你手里是旧输出，重新堆一次即可恢复。

Q: GPU 选项不见了 / 走的是 CPU？
A: 三种原因：
   1) app\gpu_runtime 文件夹被删（2.7 GB）；
   2) exe 所在路径含中文 → CuPy 的 NVRTC 打不开头文件，会静默退回 CPU，
      **请把 app 文件夹放在全英文路径下**；
   3) 显卡驱动不支持 CUDA 12。
   日志里会写“GPU 叠加失败(原因), 回退 CPU 单遍”。

Q: 识别总是“未知”？
A: 现在内置两个星表：
     · 窄视场  4°~8°   （300 mm 镜头 APS-C 约 5.4°，正好在范围内）
     · 中等   10°~30°
   5.4° 的素材会自动走窄视场库，实测能识别出 M42 猎户座大星云，并连带列出
   视场内的 NGC1980、NGC1981、M43、NGC1977。
   若仍失败（星点太少、拖线、薄云），用“或手动指定”直接写名字——
   手动指定会跳过视场检查，照样套用按类型的参数优化。

Q: 银河核心被压平了 / 细节没了？
A: 去光害太激进。把 --bg2d-q 调大（50~60）、勾上“结构保护”，
   或者干脆关掉 Background2D，改用逐帧去光污染。

Q: 边缘出现黄绿色？
A: 那是钠灯/汞灯的光谱 + 该区域单帧已经过曝。背景算法无法区分“光害”和
   “过曝的天空”，建议在后期裁掉或在 PS 里用可选颜色减黄减绿。

Q: 内存/硬盘占用？
A: 运行内存约 线程数 × 每帧 100 MB（6 线程 ≈ 2~4 GB，峰值可到 6 GB）。
   每次堆栈输出 30~70 MB 的 TIFF + 预览 + PNG。

Q: 想更快？
A: 1) 用 GPU 模式；2) 帧数多时用 onepass；3) 线程设到物理核心数；
   4) 关掉不用的后处理（bg-protect 最耗时）。
